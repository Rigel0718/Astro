앞선 글에서는 Python이 왜 정수, 문자열, 함수, 클래스까지 모두 **객체(object)​**라는 하나의 모델로 다루는지 살펴보았다.

그렇다면 이제 다음 질문이 생긴다.

```
a = 10
```

우리는 보통 이 코드를 보면서 이렇게 말한다.

> 변수 `a`에 10을 저장했다.

처음 Python을 배울 때는 충분히 좋은 설명이다.
하지만 Python의 객체 모델을 조금 더 깊게 이해하려면 이 표현에서 한 단계 더 나아갈 필요가 있다.
Python에서 `a`는 정말로 `10`이라는 값을 담고 있는 상자일까?
결론부터 말하면 그렇지 않다.

Python에서 변수는 값을 담는 상자라기보다, **객체에 붙여진 이름(name)​**에 가깝다.
그리고 `=`은 객체를 변수 안에 집어넣는 연산이라기보다,
**이름과 객체를 연결하는 연산(binding)​**으로 이해하는 것이 더 정확하다.

---
## 1. 변수는 값을 담는 상자가 아니다

C와 같은 언어를 처음 배웠다면 변수에 대해 다음과 같은 이미지를 떠올리기 쉽다.

```
int a = 10;
```

개념적으로 단순화하면 다음처럼 생각할 수 있다.
```
a
┌───────┐
│  10   │
└───────┘
```
`a`라는 저장 공간이 있고 그 안에 `10`이라는 값이 들어 있다는 그림이다.

하지만 Python의

```
a = 10
```

을 이해할 때는 다른 그림이 더 적절하다.

```
a ───────────→ 10
	        object
```

`a`라는 이름이 있고, 그 이름이 `10`이라는 객체를 가리킨다.

여기서 중요한 것은 **이름과 객체가 서로 다른 존재라는 것**이다.
`a`가 객체 자체인 것이 아니다.
`a`는 객체를 코드에서 찾아가기 위한 이름이다.

---
## 2. 하나의 객체에 여러 이름이 붙을 수 있다.

이 차이는 다음 코드를 보면 더 명확해진다.

```
a = [1, 2, 3]
b = a
```

상자 모델로 생각하면 `a` 안의 리스트가 `b`로 복사된 것처럼 느껴질 수 있다.

하지만 실제 의미는 다르다.

```
a ─────┐
       │
       ├────────→ [1, 2, 3]
       │            object
b ─────┘
```

`b = a`는 리스트 객체를 하나 더 만드는 것이 아니다.

`a`가 가리키고 있던 객체에 `b`라는 이름도 연결한다.

따라서 현재는
```
이름                 객체

a ─────┐
       ├────────→ [1, 2, 3]
b ─────┘
```

와 같은 관계가 만들어진다.

이것을 확인해보자.

```
a = [1, 2, 3]
b = a

b.append(4)

print(a)
```

결과는 다음과 같다.

```
[1, 2, 3, 4]
```

`b`를 통해 리스트를 수정했는데 `a`에서도 변화가 보인다.

이유는 간단하다.

`a`의 리스트가 `b`로 복사된 것이 아니라, **두 이름이 같은 객체를 가리키고 있었기 때문이다.**

---
## 3. 객체가 변하는 것과 이름이 다른 객체를 가리키는 것은 다르다.

여기서 Python을 이해할 때 매우 중요한 구분이 하나 등장한다.

다음 두 코드는 전혀 다른 일을 한다.

```
a = [1, 2, 3]
a.append(4)
```

그리고

```
a = [1, 2, 3]
a = [4, 5, 6]
```

첫 번째 코드는 `a`가 가리키는 **객체 자체를 변경한다.**

```
a ───→ [1, 2, 3]
          ↓
       [1, 2, 3, 4]
```

반면 두 번째 코드는 기존 객체를 다른 객체로 변화시키는 것이 아니다.

`a`라는 이름을 **새로운 객체에 다시 연결한다.**

```
처음

a ─────→ [1, 2, 3]


이후

          [1, 2, 3]

a ─────→ [4, 5, 6]
```
참고로 rebinding되어 참조되지 않은 기존 리스트 `[1,2,3]`은 gc에 의해 삭제된다. 추후에 다룰 예정이다. 

이러한 동작을 **rebinding**이라고 생각할 수 있다.

즉,

```
a.append(4)
```

는 객체의 변경이고,

```
a = [4, 5, 6]
```

는 이름의 재연결이다.

이 둘의 차이는 이후 **mutable / immutable** 객체, 함수 인자 전달, 얕은 복사와 깊은 복사를 이해할 때 계속해서 등장한다.

---
## 4. `=`은 복사가 아니라 binding이다

이제 다음 코드를 다시 보자.

```
a = [1, 2, 3]
b = a
```

Python에서 `=`을 볼 때 단순히

> 오른쪽 값을 왼쪽 변수에 복사한다.

라고 생각하면 여러 동작이 이상하게 느껴진다.

대신 다음처럼 생각하는 것이 좋다.

> 오른쪽 표현식을 평가하여 객체를 얻고, 그 객체를 왼쪽 이름에 연결한다.

예를 들어

```
result = 1 + 2
```

가 있다면 개념적으로는

```
1 + 2
  │
  │ 표현식 평가
  ▼
  3 object
  ▲
  │ binding
result
```

라고 볼 수 있다.

즉 Python의 assignment를 이해할 때 중요한 두 단계는

```
expression evaluation
        ↓
      object
        ↓
name binding
```

이다.

이 관점을 가지면 Python의 여러 문법이 하나의 모델로 연결되기 시작한다.

---
## 5. 이름은 객체의 일부가 아니다.

여기서 한 가지 오해를 피해야 한다.

```
a = [1, 2, 3]
```

이라고 했다고 해서 리스트 객체가 자신의 이름이 `a`라는 사실을 알고 있는 것은 아니다.

`a`는 객체 내부에 저장된 이름이 아니다.

오히려 Python이 현재 실행 중인 **namespace**에서

```
"a" → 어떤 객체
```

라는 관계를 관리한다고 생각하는 편이 좋다.

그래서 하나의 객체에 여러 이름이 붙을 수도 있다.

```
a = [1, 2, 3]
b = a
c = a
```

```
a ─────┐
b ─────┼────→ [1, 2, 3]
c ─────┘
```

객체 입장에서는 `a`, `b`, `c`라는 세 개의 이름을 가지고 있는 것이 아니다.

서로 다른 이름들이 우연히 같은 객체를 가리키고 있을 뿐이다.

이 차이는 생각보다 중요하다.

Python에서 **객체(object)​**와 **이름(name)​**은 별개의 개념이기 때문이다.

---
## 6. 변수의 타입이 바뀌는 것처럼 보이는 이유

Python에서는 이런 코드도 가능하다.

```
a = 10
a = "hello"
a = [1, 2, 3]
```

흔히 이를 보고

> Python에서는 변수의 타입이 계속 바뀔 수 있다.

라고 설명한다.

실용적으로는 크게 틀린 표현은 아니지만, 객체 모델의 관점에서는 조금 다르게 볼 수 있다.

```
a ───→ 10
```

에서

```
a = "hello"
```

가 실행되면

```
10

a ───→ "hello"
```

가 되고, 다시

```
a = [1, 2, 3]
```

가 실행되면

```
10

"hello"

a ───→ [1, 2, 3]
```

가 된다.

즉 `a`라는 어떤 저장 공간의 타입이

```
int → str → list
```

로 변신한 것이 아니다.

`**a**`**라는 이름이 서로 다른 타입의 객체에 차례로 binding된 것이다.**

타입은 이름 `a`의 고정된 속성이 아니라, `a`가 현재 가리키고 있는 **객체의 속성**이다.

그래서 다음과 같이 물어보는 것이 더 정확하다.

```
type(a)
```

이 코드는 본질적으로

> `a`라는 변수의 타입은 무엇인가?

보다는

> 현재 `a`라는 이름이 가리키는 객체의 타입은 무엇인가?

에 가깝다.

---
## 7. `is`와 `==`가 다른 이유도 여기서 시작된다.

Python에는 객체를 비교하는 두 가지 중요한 연산이 있다.

```
== 
is
```

예를 들어

```
a = [1, 2, 3]
b = a
c = [1, 2, 3]
```

를 생각해보자.

관계는 다음과 같다.

```
a ─────┐
       ├────→ [1, 2, 3]  object A
b ─────┘


c ──────────→ [1, 2, 3]  object B
```

`a`와 `b`는 같은 객체를 가리킨다.

하지만 `c`는 내용이 같은 별개의 객체를 가리킨다.

따라서

```
a == b   # True
a is b   # True

a == c   # True
a is c   # False
```

가 된다.

`==`는 두 객체의 **값이 같은가**를 비교하고,

`is`는 두 이름이 **동일한 객체를 가리키고 있는가**를 확인한다.

즉 Python에서는

**값이 같다**와 **같은 객체다**가 서로 다른 개념이다.

그리고 이 차이 역시 결국 이름과 객체를 분리해서 생각해야 제대로 이해할 수 있다.

---
## 8. 함수에 객체를 전달할 때도 같은 모델이 적용된다.

이름과 객체의 관계는 함수에서도 그대로 이어진다.

```
def add_item(items):
    items.append(4)

a = [1, 2, 3]
add_item(a)
```

함수가 호출되면 리스트가 통째로 함수 내부로 복사되는 것이 아니다.

개념적으로 보면

```
호출 전

a ─────────→ [1, 2, 3]


함수 호출 중

a ──────┐
        │
        ├────→ [1, 2, 3]
        │
items ──┘
```

함수의 매개변수 `items`라는 새로운 이름이 같은 객체에 연결된다.

따라서

```
items.append(4)
```

로 객체를 변경하면 함수 밖의 `a`에서도 그 변경이 보인다.

```
print(a)
# [1, 2, 3, 4]
```

반대로 함수 내부에서

```
def change(items):
    items = [4, 5, 6]
```

처럼 작성하면 이야기가 달라진다.

이것은 기존 리스트를 변경하는 것이 아니라 함수 내부의 `items`라는 이름을 새로운 객체에 **rebind**하는 것이다.

```
a ─────────→ [1, 2, 3]

items ─────→ [4, 5, 6]
```

따라서 `a`에는 영향을 주지 않는다.

이 때문에 Python의 함수 인자 전달을 단순히

> call by value인가?  
> call by reference인가?

라는 이분법으로만 이해하면 오히려 헷갈릴 수 있다.

Python에서는 **객체와 이름의 binding 관계가 함수 호출에서도 그대로 만들어진다**고 이해하는 편이 훨씬 자연스럽다.

---
## 9. 결국 Python 코드는 이름과 객체의 관계를 계속 바꾸는 과정이다.

지금까지의 내용을 조금 멀리서 바라보면 Python 코드에 대한 재미있는 관점을 얻을 수 있다.

```
a = [1, 2, 3]
b = a
b.append(4)
c = b
```

우리는 흔히 이를 변수에 값을 넣고 수정하는 과정이라고 생각한다.

하지만 객체의 관점에서 보면 Python 프로그램은 끊임없이

```
객체를 만들고
    ↓
이름을 객체에 연결하고
    ↓
객체를 사용하고
    ↓
필요하면 이름을 다른 객체에 다시 연결하는
```

과정이라고 볼 수 있다.

01편에서 이야기했던

> Everything in Python is an object.

라는 말도 이제 조금 더 구체적으로 보인다.

Python에서는 데이터를 객체라는 형태로 표현하고,

우리는 그 객체들을 **이름을 통해 찾아가며 사용한다.**

즉 Python을 이해하는 두 개의 중요한 축이 만들어진다.

```
Object
  ↑
  │ binding
  │
Name
```

**객체는 실제 데이터와 동작을 가진 존재이고, 이름은 그 객체에 접근하기 위한 연결이다.**

이 관점을 잡으면 Python에서 처음에는 서로 달라 보이던 여러 현상들이 하나의 원리로 연결되기 시작한다.

왜 리스트를 다른 변수에 대입했는데 같이 변경되는지,

왜 함수 안에서 어떤 수정은 밖에 영향을 주고 어떤 대입은 영향을 주지 않는지,

왜 `is`와 `==`가 따로 존재하는지,

왜 Python에서는 변수의 타입이 자유롭게 바뀌는 것처럼 보이는지.

그 출발점에는 모두 **이름과 객체의 관계**가 있다.

---
## 다음 글로 연결

그런데 여기까지 이야기하면 자연스럽게 한 가지 의문이 남는다.

우리는 계속해서

```
a ─────────→ object
```

라는 그림을 사용했다.

그렇다면 이 화살표는 실제로 무엇일까?

그리고 우리가 계속 이야기한 **객체**라는 것은 컴퓨터 메모리 안에서 실제로 어떻게 존재할까?

```
a = 10
```

이 한 줄이 실행됐을 때 메모리에서는 정말 무엇이 만들어지고 있는 것일까?

여기서부터는 Python이라는 언어의 개념만으로는 충분하지 않다.

Python의 대표적인 구현체인 **CPython** 내부로 한 단계 내려가야 한다.

03편에서는 지금까지 개념적으로만 사용했던

```
name ─────→ object
```

라는 그림을 실제 구현의 관점에서 바라본다.

`PyObject`는 무엇인지, Python 객체는 메모리에 어떤 정보를 가지고 있는지, 이름이 객체를 가리킨다는 것이 CPython 수준에서는 무엇을 의미하는지, 그리고 reference count가 왜 객체와 함께 등장하는지를 살펴본다.
