03편에서는 File Descriptor(FD)의 개념과 프로세스의 FD 테이블, 커널의 열린 파일 정보가 어떻게 연결되는지 살펴봤다.

그런데 Python 프로그램은 파일을 직접 열지 않아도 다음과 같이 데이터를 출력할 수 있다.

```python
print("Hello, World!")
```

일반적인 터미널 환경에서는 이 문자열이 화면에 나타난다.

반면 다음 명령어를 실행하면 화면에 출력되는 대신 파일에 저장된다.

```bash
python main.py > output.txt
```

Python 코드에서는 출력할 대상을 변경하지 않았는데 어떻게 이런 일이 가능할까?

이를 이해하려면 표준 입출력(Standard I/O)과 I/O Redirection의 개념을 알아야 한다.

이번 편에서는 stdin, stdout, stderr의 역할을 살펴보고, FD 테이블을 통해 표준 입출력의 연결 대상이 변경되는 과정을 알아본다.

---

## 1. 표준 입출력이란 무엇인가?

표준 입출력(Standard I/O)은 프로그램이 데이터를 입력받고 출력하기 위해 사용하는 기본적인 입출력 통로다.

Unix 계열 운영체제에서는 일반적으로 다음 세 가지 표준 스트림을 사용한다.

| 이름 | FD | 역할 |
|---|---:|---|
| stdin | 0 | 표준 입력 |
| stdout | 1 | 표준 출력 |
| stderr | 2 | 표준 오류 출력 |

여기서 0, 1, 2는 각 스트림에 관례적으로 할당되는 FD 번호다.

03편에서 살펴봤듯이 FD는 프로세스의 FD 테이블에서 열린 파일 등의 I/O 자원을 참조하기 위한 정수다.

따라서 표준 입출력도 FD 테이블을 통해 실제 입출력 대상과 연결된다.

일반적인 터미널 환경에서는 stdin, stdout, stderr가 터미널 장치와 연결되어 있다.

여기서 터미널은 표준 입출력이 연결되는 대상이다. 실제 터미널 환경에서는 터미널 에뮬레이터와 운영체제의 터미널 장치가 함께 관여할 수 있다.

또한 모든 프로세스의 표준 입출력이 반드시 터미널에 연결되는 것은 아니다.

파일이나 Pipe에 연결될 수도 있고, 실행 환경에 따라 일부 FD가 닫혀 있을 수도 있다.

### Python에서 표준 입출력 사용하기

Python에서는 `sys` 모듈을 통해 표준 스트림에 접근할 수 있다.

```python
import sys

print(sys.stdin)
print(sys.stdout)
print(sys.stderr)
```

대표적인 Python 함수와 표준 스트림의 관계는 다음과 같다.

| Python 코드 | 기본적으로 사용하는 스트림 |
|---|---|
| `input()` | stdin |
| `print()` | stdout |
| `print(..., file=sys.stderr)` | stderr |

예를 들어 다음 코드는 표준 출력과 표준 오류 출력에 각각 메시지를 기록한다.

```python
import sys

print("Normal output")
print("Error message", file=sys.stderr)
```

일반적인 터미널에서는 두 메시지가 모두 화면에 나타날 수 있다.

하지만 stdout과 stderr는 서로 다른 FD를 사용하기 때문에 각각 다른 대상으로 연결할 수 있다.

## 2. 표준 입출력과 FD 테이블

표준 입출력도 일반적인 FD와 마찬가지로 프로세스의 FD 테이블을 통해 관리된다.

일반적인 터미널 환경에서 실행된 Python 프로세스의 FD 테이블을 단순화하면 다음과 같다.

| FD | 표준 스트림 | 연결 대상 |
|---|---|---|
| 0 | stdin | 터미널 |
| 1 | stdout | 터미널 |
| 2 | stderr | 터미널 |

이때 Python 프로그램이 `print()`를 실행하면 일반적으로 stdout을 통해 데이터를 출력한다.

stdout은 기본적으로 FD 1과 연결되어 있으므로, 최종적으로 FD 1이 참조하는 대상으로 데이터가 전달된다.

다만 Python의 `print()`가 매번 즉시 `write` 시스템 호출을 실행하는 것은 아니다.

Python의 표준 스트림에는 버퍼링과 텍스트 인코딩 등의 처리가 포함될 수 있다.

따라서 `print()`로 작성한 문자열은 Python의 스트림 처리 과정을 거쳐 운영체제에 전달된다.

이번 편에서는 버퍼링의 세부 구현보다 FD가 어떤 입출력 대상과 연결되는지에 집중한다.

## 3. I/O Redirection은 어떻게 동작하는가?

I/O Redirection은 프로그램의 표준 입력이나 표준 출력을 다른 대상으로 연결하는 기능이다.

Linux 셸에서는 `>`, `<`, `2>` 등의 연산자를 사용해 리다이렉션을 지정할 수 있다.

예를 들어 다음 명령어를 살펴보자.

```bash
python main.py > output.txt
```

이 명령어는 Python 프로그램의 stdout을 `output.txt` 파일로 연결한다.

Python 프로그램 내부에서 `print()`의 코드를 수정할 필요는 없다.

셸이 프로그램을 실행하기 전에 표준 출력의 연결 대상을 변경하기 때문이다.

### 3.1. 리다이렉션 이전

리다이렉션이 없는 일반적인 터미널 환경에서는 FD 1이 터미널에 연결되어 있다.

따라서 `print()`로 출력한 데이터가 터미널에 나타난다.

### 3.2. 리다이렉션 이후

이번에는 다음 명령어를 실행한다고 가정하자.

```bash
python main.py > output.txt
```

셸은 Python 프로그램이 실행될 때 FD 1이 터미널 대신 `output.txt`를 참조하도록 설정한다.

여기서 중요한 점은 Python의 `print()`가 변경된 것이 아니라는 것이다.

**FD 1이 참조하는 대상이 변경되었기 때문에 동일한 출력 코드가 다른 대상으로 데이터를 전달하는 것이다.**

이러한 구조 덕분에 프로그램은 자신이 터미널에 출력하는지, 파일에 출력하는지 알지 못해도 동일한 방식으로 데이터를 기록할 수 있다.

## 4. 셸은 어떻게 FD의 연결 대상을 변경하는가?

03편에서는 `os.dup()`을 사용하면 서로 다른 FD가 동일한 열린 파일 정보를 공유할 수 있다는 점을 살펴봤다.

리다이렉션을 이해할 때는 `dup2()`도 중요하다.

`dup2(oldfd, newfd)`는 `newfd`가 `oldfd`와 동일한 열린 파일 정보를 참조하도록 만든다.

이때 `newfd`가 이미 열려 있다면 기존 연결은 교체된다.

예를 들어 셸이 다음 명령어를 실행한다고 가정해 보자.

```bash
python main.py > output.txt
```

전형적인 Unix 계열 셸의 처리 과정을 단순화하면 다음과 같다.

1. 셸이 자식 프로세스를 생성한다.
2. 자식 프로세스에서 `output.txt`를 연다.
3. `dup2()` 등을 이용해 FD 1이 해당 파일을 참조하도록 변경한다.
4. `execve()` 등을 통해 Python 인터프리터를 실행한다.

이 과정은 다음과 같은 Python 코드로 개념을 표현할 수 있다.

```python
import os

fd = os.open(
    "output.txt",
    os.O_WRONLY | os.O_CREAT | os.O_TRUNC,
    0o644,
)

os.dup2(fd, 1)

os.close(fd)
```

이 코드를 실행하면 FD 1이 `output.txt`를 참조하도록 변경된다.

이후 FD 1을 통해 출력되는 데이터는 해당 파일로 전달된다.

단, 위 코드는 리다이렉션의 핵심 원리를 보여주기 위한 예시다. 실제 셸은 프로세스 생성, 오류 처리, FD 상속 등 추가적인 작업을 수행한다.

또한 `os.dup2()`는 새로운 파일을 여는 함수가 아니다.

이미 열린 FD가 참조하는 열린 파일 정보를 다른 FD에서도 참조하도록 만드는 함수다.

## 5. Python으로 리다이렉션 확인하기

이번에는 Python 프로그램을 작성하고 실제로 표준 출력을 파일에 연결해 보자.

다음 코드를 `main.py`에 작성한다.

```python
import sys

print("Hello, stdout!")
print("Hello, stderr!", file=sys.stderr)
```

먼저 일반적인 방법으로 실행한다.

```bash
python main.py
```

터미널에서 두 메시지를 확인할 수 있다.

이번에는 stdout을 파일로 리다이렉션해 보자.

```bash
python main.py > output.txt
```

이제 터미널에는 일반적으로 다음 메시지만 나타난다.

```text
Hello, stderr!
```

반면 `output.txt`에는 다음 내용이 저장된다.

```text
Hello, stdout!
```

이는 stdout과 stderr가 서로 다른 FD를 사용하기 때문에 가능한 동작이다.

### stderr도 파일로 리다이렉션하기

이번에는 stderr를 별도의 파일로 연결해 보자.

```bash
python main.py > output.txt 2> error.txt
```

여기서 `2>`는 FD 2, 즉 stderr를 리다이렉션하는 구문이다.

실행 결과는 다음과 같다.

| 파일 | 내용 |
|---|---|
| `output.txt` | `Hello, stdout!` |
| `error.txt` | `Hello, stderr!` |

stdout과 stderr를 하나의 파일로 합칠 수도 있다.

```bash
python main.py > combined.txt 2>&1
```

여기서 `2>&1`은 FD 2가 현재 FD 1과 동일한 열린 파일 정보를 참조하도록 설정한다.

앞서 `> combined.txt`를 통해 FD 1이 파일에 연결되었으므로, FD 2도 같은 파일을 참조하게 된다.

주의할 점은 리다이렉션의 순서가 중요하다는 것이다.

```bash
python main.py 2>&1 > combined.txt
```

이 명령어에서는 먼저 FD 2를 당시 FD 1이 참조하던 대상으로 연결한 뒤, FD 1을 파일로 변경한다.

따라서 일반적인 터미널 환경에서는 stderr가 터미널에 남고 stdout만 파일에 저장된다.

다만 stdout과 stderr를 같은 파일에 연결하더라도 버퍼링 때문에 실제 출력 순서가 Python 코드의 실행 순서와 다르게 나타날 수 있다.

## 6. 표준 입력도 리다이렉션할 수 있다

지금까지는 출력 방향을 변경하는 방법을 살펴봤다.

표준 입력도 다른 대상으로 연결할 수 있다.

다음 코드를 작성해 보자.

```python
# main.py

name = input("Name: ")
print(f"Hello, {name}!")
```

일반적인 터미널 환경에서 실행하면 프로그램은 사용자가 입력할 때까지 기다린다.

```bash
python main.py
```

하지만 다음과 같이 입력 파일을 지정할 수도 있다.

```bash
echo "Python" > input.txt
python main.py < input.txt
```

`<` 연산자는 파일을 stdin에 연결한다.

따라서 `input()`은 키보드 입력 대신 `input.txt`에서 데이터를 읽는다.

이처럼 프로그램은 표준 입력의 연결 대상이 변경되더라도 동일한 입력 코드를 사용할 수 있다.

## 7. 정리

이번 편에서는 표준 입출력과 I/O Redirection의 동작 원리를 살펴봤다.

핵심 내용을 정리하면 다음과 같다.

1. 표준 입출력은 프로그램이 사용하는 기본적인 입출력 통로이며, 관례적으로 stdin은 FD 0, stdout은 FD 1, stderr는 FD 2를 사용한다.
2. 표준 입출력도 프로세스의 FD 테이블을 통해 실제 입출력 대상과 연결된다.
3. I/O Redirection은 표준 입출력의 연결 대상을 터미널에서 파일 등 다른 대상으로 변경하는 기능이다.
4. `dup2()`는 특정 FD가 다른 FD와 동일한 열린 파일 정보를 참조하도록 만드는 데 사용된다.
5. 프로그램은 표준 입출력의 연결 대상이 변경되어도 동일한 입출력 코드를 사용할 수 있다.

이제 Python 프로그램이 출력한 데이터가 어떻게 터미널이나 파일로 전달되는지 이해했다.

그런데 표준 입출력을 파일뿐만 아니라 다른 프로세스와 연결할 수도 있을까?

예를 들어 한 Python 프로그램의 stdout을 다른 Python 프로그램의 stdin에 연결하면 어떻게 될까?

다음 편에서는 **Pipe와 subprocess를 통해 프로세스가 서로 데이터를 주고받는 과정**을 살펴본다.
