04편에서는 stdin, stdout, stderr의 역할과 I/O Redirection의 동작 원리를 살펴봤다.

특히 표준 입출력은 항상 터미널에 연결되는 것이 아니라, FD가 참조하는 대상을 변경하면 파일 등 다른 곳으로 연결할 수 있다는 점을 확인했다.

그렇다면 표준 입출력을 파일이 아닌 다른 프로세스에 연결할 수도 있을까?

예를 들어 Python 프로그램에서 또 다른 Python 프로그램을 실행하고, 실행한 프로그램에 데이터를 전달한 뒤 결과를 돌려받는 상황을 생각해 보자.

이러한 프로세스 간 통신을 구현하는 방법 중 하나가 Pipe다.

이번 편에서는 부모·자식 프로세스의 관계와 Pipe의 동작 원리를 알아보고, Python의 `subprocess`를 이용해 실제로 프로세스 사이에서 데이터를 주고받아 본다.

---

## 1. 프로세스는 어떻게 서로 데이터를 주고받는가?

01편에서는 프로그램을 실행하면 운영체제가 프로세스를 생성하고, 각 프로세스에 독립적인 가상 주소 공간을 제공한다는 점을 살펴봤다.

따라서 일반적인 상황에서 한 프로세스는 다른 프로세스의 메모리에 직접 접근할 수 없다.

그렇다면 프로세스 사이에서 데이터를 주고받으려면 어떻게 해야 할까?

운영체제는 이를 위한 여러 IPC(Inter-Process Communication) 메커니즘을 제공한다.

대표적으로 Pipe, Socket, Shared Memory 등이 있다.

이번 편에서는 이 중 Pipe를 살펴본다.

Pipe는 한쪽에서 기록한 바이트 데이터를 다른 쪽에서 읽을 수 있도록 운영체제가 제공하는 통신 통로다.

일반적인 익명 Pipe(Anonymous Pipe)는 단방향 통신을 위한 읽기 끝(Read End)과 쓰기 끝(Write End)을 가진다.

```mermaid
flowchart LR
    A["Process A"] -->|"write()"| P["Pipe"]
    P -->|"read()"| B["Process B"]
```

Process A가 Pipe에 데이터를 기록하면 Process B는 같은 Pipe에서 데이터를 읽을 수 있다.

이때 Pipe의 데이터는 일반 파일에 기록되는 것이 아니라 커널이 관리하는 Pipe 버퍼를 거쳐 전달된다.

단, Pipe는 메시지 단위가 아니라 바이트 스트림을 제공한다. 한 번의 `write()`가 반드시 상대방의 한 번의 `read()`에 대응하는 것은 아니다.

## 2. 부모 프로세스와 자식 프로세스

한 프로세스가 다른 프로세스를 생성하면 일반적으로 생성한 쪽을 부모 프로세스(Parent Process), 생성된 쪽을 자식 프로세스(Child Process)라고 부른다.

01편에서 살펴본 Unix 계열 운영체제의 `fork()`와 `execve()`를 떠올려 보자.

- `fork()`는 기존 프로세스를 기반으로 자식 프로세스를 생성한다.
- `execve()`는 현재 프로세스에서 실행 중인 프로그램 이미지를 새로운 프로그램으로 교체한다.

일반적인 Unix 계열 환경에서 셸이나 다른 프로그램이 자식 프로세스를 실행할 때 이러한 메커니즘을 활용할 수 있다.

Python에서는 `subprocess` 모듈을 사용해 다른 프로그램을 실행할 수 있다.

```python
import subprocess

process = subprocess.Popen(["python", "--version"])

process.wait()
```

`Popen()`은 새로운 프로세스를 시작하고 이를 관리하기 위한 객체를 반환한다.

`wait()`는 자식 프로세스가 종료될 때까지 기다린 뒤 종료 상태 코드를 반환한다.

다만 `subprocess`가 내부적으로 반드시 `fork()`를 직접 호출하는 것은 아니다. Python 버전과 실행 환경에 따라 `posix_spawn()` 등의 메커니즘을 사용할 수도 있다.

중요한 것은 부모 프로세스가 자식 프로세스를 생성하고, 자식의 실행 상태를 관리할 수 있다는 점이다.

이제 여기에 Pipe를 연결하면 두 프로세스 사이에서 데이터를 주고받을 수 있다.

---

## 3. Pipe는 어떻게 동작하는가?

Linux에서 익명 Pipe는 `pipe()` 계열 시스템 호출을 통해 생성할 수 있다.

Python에서는 `os.pipe()`를 사용해 이를 확인할 수 있다.

```python
import os

read_fd, write_fd = os.pipe()

print(read_fd, write_fd)

os.close(read_fd)
os.close(write_fd)
```

`os.pipe()`는 두 개의 FD를 반환한다.

하나는 Pipe에서 데이터를 읽기 위한 FD이고, 다른 하나는 데이터를 기록하기 위한 FD다.

```mermaid
flowchart LR
    W["Write FD"] --> B["Kernel Pipe Buffer"]
    B --> R["Read FD"]
```

Pipe의 읽기 끝과 쓰기 끝은 각각 프로세스의 FD 테이블을 통해 참조된다.

따라서 Pipe 역시 03편에서 살펴본 FD 메커니즘을 사용한다.

### Python으로 Pipe 확인하기

하나의 프로세스에서도 Pipe를 생성하고 데이터를 주고받을 수 있다.

```python
import os

read_fd, write_fd = os.pipe()

os.write(write_fd, b"Hello, Pipe!")

data = os.read(read_fd, 100)

print(data)

os.close(read_fd)
os.close(write_fd)
```

실행 결과는 다음과 같다.

```text
b'Hello, Pipe!'
```

여기서는 동일한 프로세스가 Pipe의 양쪽 끝을 모두 사용했다.

하지만 프로세스 간 통신에서는 서로 다른 프로세스가 각각 Pipe의 끝을 사용하도록 연결할 수 있다.

## 4. 표준 입출력과 Pipe 연결하기

04편에서는 `dup2()`를 사용하면 특정 FD의 연결 대상을 변경할 수 있다는 점을 살펴봤다.

이 원리를 Pipe에도 적용할 수 있다.

예를 들어 부모 프로세스가 자식 프로세스의 stdin을 Pipe의 읽기 끝에 연결했다고 가정해 보자.

```mermaid
flowchart LR
    P["Parent Process"] -->|"write()"| B["Pipe"]
    B -->|"stdin · FD 0"| C["Child Process"]
```

부모 프로세스가 Pipe의 쓰기 끝에 데이터를 기록하면 자식 프로세스는 자신의 stdin을 통해 그 데이터를 읽을 수 있다.

자식 프로세스 입장에서는 데이터가 키보드에서 입력되었는지, 부모 프로세스가 Pipe를 통해 전달했는지 구분할 필요가 없다.

stdin에 연결된 대상으로부터 데이터를 읽으면 되기 때문이다.

반대로 자식 프로세스의 stdout을 다른 Pipe의 쓰기 끝에 연결하면 부모 프로세스가 자식의 출력을 읽을 수도 있다.

일반적인 익명 Pipe는 단방향이므로 부모가 자식에게 보내는 데이터와 자식이 부모에게 돌려주는 데이터는 서로 다른 Pipe를 통해 전달된다.

이 구조가 Python의 `subprocess`에서 stdin과 stdout을 모두 Pipe로 지정했을 때 사용되는 기본적인 통신 모델이다.

## 5. Python의 subprocess로 프로세스 간 통신하기

이번에는 실제로 부모 Python 프로그램이 자식 Python 프로그램을 실행하고 데이터를 주고받아 보자.

먼저 자식 프로그램을 작성한다.

### 자식 프로세스: child.py

```python
import sys

data = sys.stdin.read()

sys.stdout.write(data.upper())
sys.stdout.flush()
```

이 프로그램은 stdin에서 데이터를 읽은 뒤, 대문자로 변환하여 stdout에 기록한다.

여기서 `sys.stdin.read()`는 EOF(End of File)에 도달할 때까지 데이터를 읽는다.

따라서 부모 프로세스가 데이터를 전달한 후 입력 통로를 닫아야 자식 프로그램이 읽기를 마칠 수 있다.

### 부모 프로세스: parent.py

```python
import subprocess
import sys

process = subprocess.Popen(
    [sys.executable, "child.py"],
    stdin=subprocess.PIPE,
    stdout=subprocess.PIPE,
    text=True,
)

stdout, _ = process.communicate(input="hello, pipe!")

print(stdout)
```

실행 결과는 다음과 같다.

```text
HELLO, PIPE!
```

여기서 `subprocess.PIPE`는 해당 표준 스트림을 Pipe에 연결하도록 지정하는 값이다.

`stdin=subprocess.PIPE`는 부모가 자식의 표준 입력에 데이터를 전달할 수 있도록 한다.

`stdout=subprocess.PIPE`는 부모가 자식의 표준 출력을 읽을 수 있도록 한다.

`text=True`를 지정했으므로 Python은 Pipe를 통해 전달되는 바이트 데이터를 텍스트로 인코딩하거나 디코딩한다.

마지막으로 `communicate()`는 데이터를 자식에게 전달하고, 자식의 stdout에서 데이터를 읽고, 통신이 끝날 때까지 기다린다.

입력 전달을 마치면 자식의 stdin을 닫아 EOF를 전달하는 과정도 처리한다.

따라서 앞서 작성한 `sys.stdin.read()`가 정상적으로 종료될 수 있다.

## 6. Pipe를 사용할 때 주의할 점

Pipe는 단순한 구조이지만, 실제 프로그램에서는 몇 가지 주의해야 할 점이 있다.

### 6.1. Pipe의 버퍼는 무한하지 않다

Pipe의 데이터는 커널이 관리하는 제한된 크기의 버퍼를 거쳐 전달된다.

따라서 데이터를 읽는 쪽이 충분히 빠르게 데이터를 소비하지 않으면 버퍼가 가득 찰 수 있다.

일반적인 Blocking 모드에서 Pipe가 가득 찬 상태로 추가 데이터를 기록하려고 하면, 쓰기 작업은 공간이 생길 때까지 대기할 수 있다.

반대로 읽을 데이터가 없는 상태에서 Pipe를 읽으면 새로운 데이터가 도착할 때까지 대기할 수 있다.

단, 모든 쓰기 끝이 닫혔다면 읽는 쪽은 EOF를 확인할 수 있다.

이러한 동작은 다음 편에서 다룰 Blocking과 Non-blocking I/O로 이어진다.

### 6.2. 잘못된 통신 순서는 Deadlock을 일으킬 수 있다

부모 프로세스가 자식 프로세스의 stdout을 Pipe로 연결한 상황을 생각해 보자.

자식 프로세스가 많은 데이터를 출력해 Pipe 버퍼가 가득 찼는데, 부모 프로세스가 출력을 읽지 않고 자식의 종료만 기다린다면 어떻게 될까?

자식은 Pipe에 데이터를 더 기록할 수 없어서 대기하고, 부모는 자식이 종료되기를 기다리는 상황이 발생할 수 있다.

이처럼 서로의 진행을 기다리면서 더 이상 작업을 수행하지 못하는 상태를 Deadlock이라고 한다.

Python의 `subprocess`에서는 이러한 문제를 피하기 위해 `communicate()`를 사용하는 것이 일반적으로 권장된다.

`communicate()`는 입력 전달과 출력 수집을 함께 처리한다.

단, 모든 출력을 메모리에 수집하므로 출력량이 매우 큰 프로그램에서는 다른 처리 방식이 필요할 수 있다.

### 6.3. 사용하지 않는 Pipe의 끝은 닫아야 한다

Pipe에서 EOF가 발생하려면 해당 Pipe의 쓰기 끝을 참조하는 모든 FD가 닫혀야 한다.

따라서 더 이상 사용하지 않는 FD를 열어 둔 상태라면 읽는 쪽이 EOF를 받지 못하고 계속 대기할 수 있다.

부모·자식 프로세스 사이에서 Pipe를 직접 구성할 때는 각 프로세스가 사용하지 않는 Pipe의 끝을 닫는 것이 중요하다.

`subprocess`는 일반적인 통신 설정에서 이러한 FD 연결과 정리를 대신 처리해 준다.

## 7. 셸의 Pipe도 같은 원리로 동작한다

지금까지는 Python에서 `subprocess`를 사용해 Pipe를 생성했다.

Linux 셸에서도 같은 원리를 사용할 수 있다.

```bash
printf "hello\n" | tr 'a-z' 'A-Z'
```

여기서 `|` 연산자는 왼쪽 프로그램의 stdout을 오른쪽 프로그램의 stdin에 연결한다.

실행 결과는 다음과 같다.

```text
HELLO
```

셸은 두 프로그램을 실행하고, 한 프로그램의 stdout이 다른 프로그램의 stdin으로 전달되도록 Pipe를 구성한다.

이때 두 프로그램은 반드시 서로 부모·자식 관계일 필요는 없다. 일반적인 셸 파이프라인에서는 두 프로그램 모두 셸이 생성한 자식 프로세스일 수 있다.

핵심은 프로세스 간의 부모·자식 관계 자체가 아니라, **각 프로세스의 FD가 동일한 Pipe의 양쪽 끝을 참조하도록 연결되어 있다는 점**이다.

---

## 8. 정리

이번 편에서는 Pipe와 Python의 `subprocess`를 통해 프로세스 사이에서 데이터를 주고받는 과정을 살펴봤다.

핵심 내용을 정리하면 다음과 같다.

1. 서로 다른 프로세스는 일반적으로 독립적인 가상 주소 공간을 사용하므로, 데이터를 주고받기 위해 IPC 메커니즘이 필요하다.
2. Pipe는 운영체제가 제공하는 단방향 바이트 스트림 통신 통로다.
3. Pipe의 읽기 끝과 쓰기 끝은 FD를 통해 참조된다.
4. 서로 다른 두 Pipe를 사용하면 부모와 자식 프로세스 사이에서 양방향 통신을 구성할 수 있다.
5. Python의 `subprocess`는 프로세스 생성과 표준 입출력의 Pipe 연결을 편리하게 처리한다.
6. Pipe를 사용할 때는 제한된 버퍼 크기, Blocking, EOF, Deadlock 등에 주의해야 한다.

이제 한 프로세스가 다른 프로세스를 실행하고, 표준 입출력을 Pipe에 연결해 데이터를 주고받는 구조를 이해했다.
